## 一、基本要求的三条落实

| 要求 | 做法 | 可复核之处 |
|---|---|---|
| **限定班级范围** | 班级标识**仅取自登录会话**；请求体／查询串／请求头里的 `class_id` 解析后一律丢弃。`keyword` 与 `vector` **两条路径都过滤**，向量路径**回表时再核对一次** | 规约 R7/R8/R9；`tests/retrieval.e2e.js` §7；`第4课证据/06`、`07` |

## 二、变更内容一览

### 1. 存储二分：正文留在关系库，向量进向量库

切片正文 `chunk_text` 存在关系库；向量库中每个点只存**定长浮点向量 + 若干标识**，
payload 恰为 `class_id / material_id / knowledge_entry_id / chunk_id / chunk_index`，
**不含一个字的正文**。

> 为什么：摘录只能有一个来源。正文若同时存在于 payload，两侧可能不一致（重建索引、
> 预处理变更后尤其容易），届时无法判断该信哪一份。而且 `keyword` 要在向量库故障时照常
> 工作，前提就是正文与全文索引都在关系库。

`e2e` §2 断言 payload 字段**恰好**是这 5 项，且三处主键相等。

### 2. 三种切分策略

| 策略 | 参数 | 断句优先级 |
|---|---|---|
| `auto`（默认） | 最大 800 字，重叠 80 字 | 空行 → 换行 → 句号 → 强制截断 |
| `custom` | 最大 100–2000 字，重叠 0%–50% | 分隔符 → 强制截断；可选预处理 |
| `hierarchy` | 沿用 auto 上限 | `#` / `##` / `###` 分章，过长章二次切分 |

预处理**不改写** `body_text`；由此切片偏移是相对**预处理后**文本计算的 —— 这个坑写在
`design.md` 决策 3 里。

### 3. 三种检索模式

| 模式 | 访问的组件 | 排序 |
|---|---|---|
| `keyword` | 仅关系库全文索引 | 全文相关度 |
| `vector` | 问句嵌入 → 向量库按班级过滤 → 回表取正文 | 余弦相似度（**< 0.35 丢弃**） |
| `hybrid`（默认） | 同时执行两条路径 | **RRF，`k = 60`** |

融合的是**名次不是分数** —— 全文相关度与余弦相似度不在一个量纲上，直接相加会让量级大的
一路支配排序。名次分也**不是相关性阈值**，所以绝对分数过滤必须在融合之前完成。

### 4. 班级隔离

- 两条路径**都**按会话班级过滤，`keyword` 只检索 `index_status = 'ready'` 的切片；
- 向量路径**回表时再核对一次班级** —— 纵深防御，即便向量库漏加过滤也不漏数据；
- **跨班级检索返回 HTTP 200 + 空 `hits`**，刻意不用 403/404 —— 避免泄露「该资料属于
  其他班级」。代价是无法区分「权限不足」与「真的没有」，这是有意接受的。

### 5. 无依据时不调生成模型

`POST /week04/api/ask` 只用**最新一句**提问做本班 hybrid 检索，取**前 4 条**：

- 有切片 → 把「标题 + 切片序号 + 切片正文 + 提问」交给对话网关，回答用 `[1]`、`[2]`
  标注出处，顺序与 `citations` 一致；
- **无切片 → 直接返回「资料中未找到相关内容」，`citations` 为空，不调用对话网关。**

模型参数里没有本校讲义，但它是会编的。一旦在无依据时把问题交给它，回答就退化成
「凭记忆作答 + 看起来专业」—— 这恰恰是 RAG 要解决的问题。

### 6. 降级

| 情形 | 行为 |
|---|---|
| 向量库不可用 | `keyword` 照常返回；`vector` / `hybrid` 返回 **503**，不编造相似度分数 |
| 空查询 / 非法模式 | 400 |
| 嵌入失败 | 材料保留，切片标 `failed`，不写残缺点 |
| 检索无候选 | 200 + 空 `hits` + 固定文案 |

### 7. 本课不做

交叉编码器重排序（rerank）· 流式输出 · 编排框架（LangChain／LlamaIndex／Dify）·
**向量库端口对外暴露**（其自身无业务鉴权，一旦映射到宿主端口，任何人都能读走全部班级的
向量与 payload，班级隔离形同虚设）。

## 六、与参考实现的差异（诚实说明）

课程参考实现是 **Go + MySQL + Qdrant**；本项目沿用 **零第三方依赖的 Node 应用**
（只用内置 `http` / `node:sqlite` / `crypto`）。规约写的是**行为契约** —— 班级隔离、
三种模式、过滤时机、RRF `k = 60`、无依据不调模型 —— 这些与语言无关。因此做了两处
**能力等价替换**，行为契约一字不改：

| 规约假设 | 本项目实现 | 为什么仍然满足契约 |
|---|---|---|
| MySQL `FULLTEXT … WITH PARSER ngram` | 自建 **bigram 倒排表** `chunk_grams(chunk_id, gram)` | SQLite FTS5 的 `unicode61` 会把连续汉字切成一个 token，「函数与极限」搜不到「极限」—— 这正是 MySQL 要挂 ngram 解析器的原因。自建倒排等价解决了中文子串召回 |
| Qdrant 独立服务 | `vecstore.js` 的进程内 `VectorStore`，JSON 落盘 `data/vectors.json` | 集合名、度量（cosine）、「主键 = 切片 id」、「payload 只存标识」全部一致；且**本就不监听任何端口**，比「记得别映射端口」更安全 |

换回真实 Qdrant 只需替换 `vecstore.js`，上层 `retrieval.js` 的调用契约
（`upsert / delete / deleteBy / search / count`）不变。嵌入同理：配置 `EMBED_BASE_URL` /
`EMBED_API_KEY` / `EMBED_MODEL` 即切换到真实模型，`/week04/api/retrieval/meta` 会自动
回显 `embedding: "gateway"`。

**关于 `0.35` 阈值**：它是给真实语义嵌入定的。本地兜底嵌入的绝对值与真模型不可比，
因此本课对它做了实测调参并如实记录在 `第4课-实现说明与验收对照.md` 第四节 ——
应命中的 8 个问句 7 个越线，应落空的（问天气/球赛）top 余弦全部 ≤ 0.21。换成真模型时
按真模型重新校准即可，不必跟着本地口径调。

## 七、运行与演示

### 本仓库能独立做什么

本仓库包含的是**本课的变更描述、检索实现与回归测试**，不含完整应用
（`server.js` / `index.html` / `app.js` 及启动脚本不在其中）。因此**回归测试可独立运行**：

```bash
node tests/run.js          # 4 套件 / 177 条断言，从空库首启真跑
```

无需任何外部服务、无需安装依赖（只用 Node 内置模块）。

### 完整应用中的演示动线

完整应用以 `start.bat` 启动（入口 `http://localhost:8088`），演示账号：
`zhang / 123456`（张老师 · 1 班）、`li / 123456`（李老师 · 2 班）、
`s001 / 123456`（王小明 · 1 班学生）、`s002 / 123456`（陈小红 · 2 班学生）。
下列动线的界面结果已固化为 `第4课证据/` 中的截图，不启动应用也能核对。
